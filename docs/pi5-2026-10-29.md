# Raspberry Pi 5 port — progress (2026-10-29)

Not a cycle; no gate depends on it. Build: `. build/cross/env.sh && scripts/build-pi5-img.sh` → `build/pi5/cua-agentos-pi5.img`.

## What exists
- Cross build: `ARCH=aarch64 KERNEL=rpi CROSS=aarch64-linux-gnu- CROSS_RUN=qemu-aarch64-static BASE_FS=mmc` through the
  existing 04/05 builders. agent-init (static glibc), agentd (Rust, dynamic against Alpine aarch64 musl), libtier1.so.
- Image: MBR, p1 FAT32 256 MB (config.txt, cmdline.txt, Alpine `linux-rpi` 6.18 kernel, initramfs, bcm2712 DTBs,
  overlays), p2 raw SquashFS = `/dev/mmcblk0p2`. Kernel execs agent-init via `rdinit=`, then `/stage1`, then switch_root.
- No serial cable needed: stage1 mounts p1 and writes `stage1.log`, `dmesg.txt`; telemetry goes to
  `AGENT_TTY=/mnt/boot/agentos.log` (kernel cmdline env; default `/dev/ttyS0`, opened O_APPEND by agent-init and agentd).
  `agent.hold` stops everything without powering off. HDMI: `dtoverlay=vc4-kms-v3d`, `console=tty1`.
- Host tools are rootless copies of Ubuntu debs in `build/cross/` (gitignored); proper install:
  `sudo apt install gcc-aarch64-linux-gnu qemu-user-static qemu-system-arm mtools`.

## Hardware result (Pi 5 8 GB, SD card) — `build/pi5/pi5-run1-agentos.log`
Everything passes except boot time: PID1_READY 930 ms; **AGENTD_READY 4146 ms after PID1_READY (budget 3000)**;
TIER1 0.049 ms, TIER2 3.3 ms, TIER3 2.9 ms; screencopy 57.4 FPS; WORKFLOW_COMPLETE (1 replan); test-cap installed,
corrupt-cap rolled back clean; agentd exited 0. Gates 04/05/06 run on the log fail only `agentd_ready`.
Likely cause (unmeasured): `rootfs/agent-init/prep` rebuilds GTK/MIME caches and runs udev on every boot from the SD
card. Candidate fix: build those caches at image time via `qemu-aarch64-static`.

## Gotcha seen while flashing
A `dd of=/dev/sda` run while the card was unplugged created a regular file `/dev/sda`; later flashes went into it.
Flash only with `test -b /dev/sda && sudo dd ...`.
