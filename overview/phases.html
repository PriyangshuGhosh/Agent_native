Vertical-Slice Engineering Strategy

Informational grouping only Build from lowest-latency capability primitives upward.mdash; the canonical work breakdown and gates are the 8 cycles on the Timeline. Build from lowest-latency capability primitives upward. Do not attempt full OS packaging before interaction and execution loops are proven.
PHASE 1

Interaction & Semantic Primitives

Validate the core control mechanisms inside a standard Linux development environment.

  1. Launch headless Wayland compositor with a virtual display output.
  2. Extract live UI hierarchy via D-Bus AT-SPI2 calls into structured JSON.
  3. Execute actions directly via AT-SPI DoAction and SetTextContents interfaces.
  4. Inject fallback synthetic inputs via /dev/uinput.
  5. Capture screen frames via wlr-screencopy protocol at ≥10 FPS.
Gate: Deterministic script completes target UI actions headlessly with exit code 0.
PHASE 2

Custom PID 1 & Boot Infrastructure

Replace standard init systems with the dedicated agent-init binary.

  1. Implement agent-init.c with VFS mounts and signal handling.
  2. Compile minimal Linux kernel defconfig (DRM/KMS, uinput, OverlayFS).
  3. Configure bootloader with init=/usr/bin/agent-init.
  4. Initialize D-Bus session bus and headless compositor directly from PID 1.
  5. Verify boot sequence under QEMU serial console.
Gate: Serial log emits PID1_READY ≤1000ms after kernel start and AGENTD_READY ≤3000ms after PID1_READY, without systemd or display managers.
PHASE 3

3-Tier Capability Engine

Implement the autonomous capability router.

  1. Implement Tier 1: In-memory dynamic library loader (dlopen) and Wasm runner.
  2. Implement Tier 2: Headless process orchestrator with CDP WebSocket and IPC pipes.
  3. Implement Tier 3: Off-screen Wayland workspace manager with AT-SPI semantic driving.
  4. Implement pre-action validation and post-action state verification.
Gate: Agent executes 3 varied tasks across all 3 tiers with zero visual UI displayed.
PHASE 4

Lifecycle Management & Storage

Enable autonomous software acquisition and state isolation.

  1. Configure SquashFS base rootfs with OverlayFS writable branches.
  2. Implement application registry supporting CLI binaries, AppImages, and libraries.
  3. Agent autonomously fetches, stages, and executes an external capability.
  4. Implement transactional rollback on failed or corrupted installations.
Gate: Clean uninstalled capability acquired, executed, and verified end-to-end.
PHASE 5

Reproducible ISO & Evaluation

Package the verified operating system into a portable distribution artifact.

  1. Assemble reproducible hybrid ISO build pipeline.
  2. Validate automated unattended boot in QEMU under KVM.
  3. Execute complete rubric evaluation suite via guest serial link.
  4. Perform bare-metal hardware validation.
Gate: ISO boots and passes all rubric test suites autonomously.
